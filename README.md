# Krishi Sathi

**Smarter farming decisions, in your own language.**

Krishi Sathi is a local Streamlit prototype for farmers in five Andhra Pradesh districts. Select a district, soil, crop, irrigation availability and language in the sidebar. Use the section selector to move between weather and actions, crop options, mandi prices and the farmer assistant.

- **Weather & actions** shows the live location and retrieval time, a three-day forecast, and a rainfall chart with tooltips. Action cards highlight the suggested next step, severity, and the forecast evidence.
- **Crop options** shows soil fit and water needs on each card, with expandable reasoning and limitations.
- **Mandi prices** applies the crop filter to both the sample chart and table. Hover over bars for the market, price, unit and sample date.
- **Ask Krishi Sathi** accepts suggested or typed questions and keeps a conversation for each farm profile in the current browser session. New generated replies use the selected language. Earlier generated replies stay in their original language and rule-based replies follow the current toggle.

## Run locally

Use Python 3.11 or later. From the workspace root in PowerShell:

```powershell
Set-Location krishi-sathi
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

With the environment activated, the launch command is `streamlit run app.py`. The app opens at `http://localhost:8501`. Open-Meteo needs internet access and requires no API key for this prototype.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Configure generative AI

The app uses the official OpenAI Python SDK and Chat Completions. The default model is `gpt-5.4-mini`. Create a project API key in the [OpenAI platform](https://platform.openai.com/api-keys), enable API billing or credits, then run this command in the project directory.

```powershell
Copy-Item .env.example .env
```

Open `.env` in your editor and set `OPENAI_API_KEY` locally. Set `OPENAI_MODEL` to change the model. For a trusted OpenAI-compatible provider, set `OPENAI_BASE_URL` to its API base URL, typically ending in `/v1`, and supply that provider's key and model ID. The endpoint must support Chat Completions, `max_completion_tokens` and `store: false`. HTTPS is required for remote endpoints.

Process environment variables take precedence over `.env`, followed by top-level keys of the same names in `.streamlit/secrets.toml`. Keep credentials private. The project ignores `.env` and `.streamlit/secrets.toml`. Restart the running app after changing its configuration.

With the app running, open **Ask Krishi Sathi**, ask “What should a groundnut farmer check first given this forecast?” and look for **Generated by AI** on the reply. Switch to **తెలుగు**, ask “ఈ వాతావరణ అంచనా ప్రకారం వేరుశనగ రైతు ముందుగా ఏం చూడాలి?” and check for a Telugu response. In **Weather & actions**, select **Explain this alert with AI** to generate a separate explanation while the rule-based action and live forecast evidence remain in view. A configured status means a key is present. The generated label appears after a usable model response.

Each submitted question or requested explanation makes at most one model call with a 10-second SDK timeout, no automatic retries, and a cap of 650 completion tokens. At the published standard rate for GPT-5.4 mini, a call with 1,000 input tokens and 650 output tokens would cost about $0.0037. Actual costs vary by usage and provider. [GPT-5.4 mini pricing](https://developers.openai.com/api/docs/models/gpt-5.4-mini)

## How the data and rules work

- **Weather.** Open-Meteo supplies modeled current conditions and three local calendar days, including today. Each district uses the approximate coordinates of its headquarters. Daily rain combines the API's rain and shower totals. Responses are cached per district for ten minutes and show the retrieval time in IST. An outage shows an explicit status and a retry button. [Open-Meteo forecast documentation](https://open-meteo.com/en/docs)
- **Actions.** Rain from 10 to under 30 mm per day prompts an irrigation timing check. At 30 mm per day or above, drainage becomes the rain-related priority. A daily high of at least 36°C adds a heat alert independently. These are demonstration thresholds. Check conditions at the field and consider crop stage and soil moisture before acting.
- **Crop reference.** `data/crops.json` uses broad soil types, water categories, season tags, drainage sensitivity and a bilingual limitation for each crop. The entries and scores are simplified demonstration judgments informed by agricultural extension material. Soil comes from the farmer. The engine filters by soil, prioritizes suitable water availability, then considers season and short-term weather. It shows up to three options with trade-offs. The broad season convention uses June–October for kharif, November–February for rabi and March–May for summer. Confirm planting decisions locally with an agronomist. [TNAU crop production reference](https://agritech.tnau.ac.in/agriculture/CropProduction/crop_production_varieties.html) · [TNAU crop selection guide](https://agritech.tnau.ac.in/agriculture/agri_cropselect.html)
- **Mandi prices.** Every row in `data/mandi_sample.csv` is illustrative. The market and date fields provide context for the demonstration.
- **Assistant.** Generative requests send the current question and selected farm and advisory context to the configured provider. The model is instructed to use that context, state uncertainty and avoid invented measurements, prices, yields and dosages. Model text can still contain mistakes. Use the displayed Open-Meteo values and prototype alert evidence to check factual claims. If the provider is missing or a request fails, the app labels its deterministic fallback, which covers common questions about rainfall, irrigation, alerts, soil fit and planting considerations.
